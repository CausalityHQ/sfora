# Verbalizer-Margin Distillation F0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and run a Sfora-only, forward-only Qwen screen that determines whether scalar teacher margins can repair frozen SigLIP retrieval errors before any new training.

**Architecture:** A small pure-Python authority/result module validates the frozen M2/M4 relationship and recomputes all gates. A local-only runner loads the already authenticated Qwen adapter, selects immutable Cars images, scores two candidate pairs per error without gradients, writes resumable per-error observations, replays two ordinals, and publishes one canonical result. DGX execution uses an exact commit and one monitored process.

**Tech Stack:** Python 3.13, PyTorch, existing Sfora data/Qwen adapters, pytest.

**Spec:** `docs/superpowers/specs/2026-09-03-vmd-f0-design.md`

## Global Constraints

- Change only the Sfora repository; never modify Borsuk.
- F0 is train-band, claim-ineligible, forward-only, and performs no generation.
- Candidate selection is entirely fixed by authenticated M2/M4 evidence before Qwen scoring.
- No production training change is authorized unless F0 passes every frozen gate.
- Run one DGX process, retain its session, monitor at intervals no longer than 55 seconds, and never overlap or silently restart it.
