# Selected Sfora versus full-width UNICOM latency screen, 25 September 2026

The selected seed-179023 coverage-bank SigLIP2 checkpoint was faster than the authenticated UNICOM ViT-L/14@336 checkpoint in a paired **diagnostic** image-to-top-10 screen on the same DGX Spark GB10. The candidate was selected by its highest frozen SOP TRAIN-holdout bank Recall@1 before this timing. Both used the first 32 already-observed official SOP TEST images and the same remaining 60,470 TEST images as gallery. The candidate used its official evaluation precision path (fp32 weights, fp16-autocast vision, fp32 128-D head) and exact native 130-byte packed scorer. UNICOM used its official 336-pixel transform, normalized full 768-D output, first 512 coordinates **without renormalization**, and exact fp32 Euclidean-equivalent scoring with stable ordinal ties. All ten returned rows are nonself because the 32 query images are excluded from both galleries.

Batch-1 median encode was 17.074 versus 29.892 ms and search 0.332 versus 0.683 ms; batch-32 encode was 266.673 versus 390.759 ms and search 0.706 versus 2.641 ms. Decode and preprocessing were included in end-to-end time. Candidate gallery wire storage was 7,861,100 bytes versus 123,842,560 bytes for the reference 512-float prefix. Peak CUDA allocation while both models and galleries were resident was 5,643,059,200 bytes; peak host RSS was 12,427,894,784 bytes. The [raw receipt](evidence/compact_metric/sop-siglip2-substrate-v1/coverage-vs-fullwidth-unicom-diagnostic-v1.json) has SHA-256 `00554a6cfe88257fd3d9c53f59b14077e5cc6300358ca024dd4a5e00d13a95f8`; the successful unit invocation `49d36387cabd46819b3ccc6ed3d9ef15` [journal](evidence/compact_metric/sop-siglip2-substrate-v1/coverage-vs-fullwidth-unicom-diagnostic-v1.log) has SHA-256 `65f8c71df943e1385112d1d4594c329c4ce0f0038c8d1369fd2fa8241b57ad62`.

The first preflight attempt stopped before timing because batch-32 live candidate top-10 lists differed from the cached batch-64 official export; its [failure journal](evidence/compact_metric/sop-siglip2-substrate-v1/coverage-vs-fullwidth-unicom-first-parity-failure-v1.log) has SHA-256 `437e03d44f6d1652114a827372e86d38a4ea570a509d9fb4a7c68f402cbcf470`. The diagnostic found exact cached native-versus-scalar scorer parity, **32/32 live top-1 parity**, and **26/32 live top-10 parity** at batch 32. Repeating the same queries in a batch of 64 restored **32/32 top-10 parity** with the official cached export. The discrepancy therefore follows encoder batch shape; it is not a search arithmetic difference. The timed batch-1 and batch-32 paths have not had full official TEST quality measured. The prior 91.2725% Recall@1 mean describes the batch-64 export, not automatically these serving batches.

**Decision:** this screen passes the cheap latency falsifier and supports further product work. It does not satisfy the p99 gate (10,000 calls per cell and block-bootstrap confidence interval), nor establish a joint quality/performance win. First measure the deployed batch-1 and batch-32 official TEST quality at the selected checkpoint or make the live inference path numerically invariant to batch size. Then port the frozen bank-versus-float recipe to In-Shop with singleton handling and evaluate its official query/gallery protocol. A full p99 certification follows only for a candidate that clears both quality datasets.
