

## Operator policy: contextless specialists and simulated perspectives

Use Devbox `specialist_start` by default for each separable bounded plan,
implementation, test or evidence audit. Specialists start with no inherited
conversation, transcript, reasoning history or preferred conclusion. Supply
only a self-contained task, relevant code and exact base, factual requirements,
constraints and acceptance checks. The root reconciles proposals with prior
experiments, verifies results and integrates changes. Keep experiment and
spending authority with the root; do not duplicate children or consultations.
Each specialist is single-use: finish that bounded task with a verified handoff,
then close it. If the task grows, compact at a safe checkpoint or hand off to
the root instead of retaining a long-lived specialist.

Treat LLMs as simulators of perspectives, not entities with personal,
long-held opinions. For exploration, do not ask "What do you think about X?"
Ask "Which people would be useful to explore X, and what would each say?"
Simulate their arguments, objections and predictions, then synthesize
falsifiable claims. These generated viewpoints reflect training, not actual
consultations, independent evidence or consensus. Verify consequential claims
against primary sources, code and measurements. Use a small relevant group
(for example a retrieval researcher, systems engineer, statistician and
skeptical practitioner); do not add ceremonial panels to trivial tasks or
duplicate paid reviews.

Retain valid quality gains as Pareto improvements even when memory or runtime
targets miss, then optimize efficiency while preserving quality. Operational
hard ceilings, measurement validity and spending authorization still apply.
